# Personal Manager

Небольшой персональный менеджер для одного пользователя: события, напоминания,
регулярные расходы, входящие письма и уведомления. Источник истины — SQLite;
внешние сервисы используются только как вспомогательные каналы.

## Возможности

- **События** — разовые и ежегодные (`yearly`), корректная обработка 29 февраля.
- **Напоминания** — производные от событий: «в день» и «за N дней», уникальность по паре (событие, дата).
- **Регулярные расходы** — ежемесячные/квартальные/годовые; суммы хранятся в целых минимальных единицах (копейках), расчёт даты следующего платежа.
- **Отслеживание задач** — таблица `job_runs` (pending/running/success/failed), детекция «зависших» задач и восстановление при запуске.
- **Telegram-уведомления** — только важные события (провал задачи, прерванная задача).
- **Google Sheets** — человеческий интерфейс: двусторонняя синхронизация событий и расходов (новая строка с пустым ID создаёт запись и получает ID; удаление строки ничего не удаляет), экспорт напоминаний.
- **Входящие + классификация DeepSeek** — категория, важность, резюме, флаг «требует действия».
- **Gmail** — read-only импорт писем от разрешённых отправителей (точное сравнение адреса).

## Архитектура

SQLite — единственный источник истины; бизнес-логикой владеет Python. APScheduler
только запускает задачи, а их состояние живёт в БД. Google Sheets — интерфейс для
человека, Telegram — канал уведомлений, Gmail — read-only источник писем, DeepSeek —
только семантическая классификация. LLM никогда не пишет в БД напрямую и не
выполняет детерминированные расчёты.

## Конфигурация

Скопируйте `.env.example` в `.env` и заполните нужные значения. Файл `.env` не
попадает в Git. Все переменные опциональны — без них приложение запускается, а
соответствующая интеграция просто отключена.

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `LOG_LEVEL` | Уровень логирования | `INFO` |
| `DATABASE_URL` | URL SQLite (SQLAlchemy async) | `sqlite+aiosqlite:///./data/personal_manager.sqlite3` |
| `JOB_STALE_TIMEOUT_SECONDS` | Через сколько секунд `running`-задача считается зависшей | `3600` |
| `TELEGRAM_BOT_TOKEN` | Токен бота Telegram (пусто — Telegram отключён) | — |
| `TELEGRAM_CHAT_ID` | ID чата для уведомлений (пусто — уведомления отключены) | — |
| `TELEGRAM_POLL_TIMEOUT` | Таймаут long polling | `30` |
| `GOOGLE_SERVICE_ACCOUNT_FILE` | Путь к JSON service-account для Sheets | — |
| `GOOGLE_SPREADSHEET_ID` | ID таблицы Google Sheets | — |
| `DEEPSEEK_API_KEY` | Ключ DeepSeek (пусто — классификация отключена) | — |
| `DEEPSEEK_MODEL` | Модель DeepSeek | `deepseek-chat` |
| `DEEPSEEK_TIMEOUT_SECONDS` | Таймаут запроса к DeepSeek | `30` |
| `GMAIL_CLIENT_SECRET_FILE` | Путь к OAuth client-secret JSON | — |
| `GMAIL_TOKEN_FILE` | Путь к OAuth token JSON | — |
| `GMAIL_MAX_MESSAGES` | Лимит импортируемых писем за запуск | `100` |

Пути `GOOGLE_SERVICE_ACCOUNT_FILE`, `GMAIL_CLIENT_SECRET_FILE` и `GMAIL_TOKEN_FILE`
указывают на внешние credential-файлы; сами файлы не должны попадать в репозиторий.

## Заполнение таблицы Google Sheets

Листы `Events` и `Expenses` — это ввод и редактирование. Новая запись: заполните строку и **оставьте
колонку `ID` пустой**: через несколько секунд после того, как вы закончили печатать, приложение
создаст запись и впишет в `ID` номер. Строка с ошибкой пропускается и остаётся как есть, остальные
строки импортируются.

**Обратная связь на ячейке `ID`.** После каждой проверки ячейка `ID` окрашивается:
зелёная — строка принята, красная — не принята. Наведите курсор: в примечании видно, **как бот
понял строку** (значения из базы, включая вычисленные даты напоминаний) или **почему строка не
принята** и что допустимо. Свои цвета и заметки в колонке `ID` бот перезапишет.

**Что можно менять в таблице.**

| Действие | Можно? |
|---|---|
| Переименовать вкладку, переставить вкладки местами | да — бот находит листы по скрытой метке, а не по имени или месту |
| Переименовать заголовок любой колонки | да — колонки определяются по порядку, а не по названию; первая строка всегда заголовок |
| Поменять колонки местами или вставить колонку внутрь таблицы | нет — порядок колонок фиксирован |
| Писать свои заметки правее таблицы | да: в Events с колонки `J`, в Expenses с колонки `K` (колонки `H`, `I` в Events заполняет бот) |
| Вставлять пустые строки, сортировать | да |
| Свой формат даты или суммы (например «суббота, 24 августа», «2 500 ₽») | да — бот читает само значение, а не то, что показано |
| Сумма, у которой формат ячейки скрывает значение (например сумма `12.5`, показанная как дата) | строка отклоняется с объяснением в примечании; сбросьте формат (Формат → Число → Автоматически) и введите сумму заново |
| Галочка в колонке «Активно» | да — остаётся галочкой, бот не заменяет её словом |
| Строка только с вашей заметкой (без ID, названия и т. д.) | игнорируется, ошибкой не считается; чужие строки бот не переписывает |
| Удалить строку | не удалит запись: строка вернётся. Чтобы удалить запись, напишите в колонке «Активно» слово `удалить` (регистр не важен) — запись удалится вместе с её напоминаниями, строка очистится |

**Events** — обязательны `Событие` и `Дата`:

| Колонка | Что писать |
|---|---|
| Дата | `24.12.2026` или `2026-12-24`; у ежегодных событий бот хранит ближайшее наступление |
| Повтор | один раз: `none`, `разово`, `один раз`; каждый год: `yearly`, `ежегодно`, `каждый год`, `через год`. Других интервалов у событий нет (ежемесячные платежи — лист Expenses) |
| Напоминание | за сколько дней напомнить: `3`, `за 15 дней`, `за день до события`, `за неделю`, `в день события`; несколько — через запятую или «и»: `0, 15`, `за 15 дней и за 3 дня` |
| Что сделать | любой текст |
| Активно | `да` / `нет` (или галочка): при `нет` событие на паузе — напоминаний нет и на следующий год оно не сдвигается; пусто = `да`; `удалить` — удалить запись |
| Когда будет напомнено | заполняет бот: дата ближайшего напоминания |
| Когда событие случится | заполняет бот: дата ближайшего наступления события |

**Expenses** — обязательны `Название`, `Сумма`, `Валюта`, `День оплаты`, `Следующая оплата`:

| Колонка | Что писать |
|---|---|
| Сумма | `1000`, `12,50`, `1 000,50` |
| Валюта | `RUB`, `USD`, `EUR` (или `₽`, `$`, `€`, `руб`) |
| Период | `monthly` / `ежемесячно`, `quarterly` / `ежеквартально`, `yearly` / `ежегодно` (пусто = monthly) |
| День оплаты | число от 1 до 31 |
| Следующая оплата | дата, как в Events |
| Активен | `да` / `нет` (или галочка); `удалить` — удалить запись |
| Напомнить за (дн.) | за сколько дней напомнить о платеже: `3` или `за 3 дня` (одно значение; пусто = 3) |

Пустая ячейка при редактировании существующей строки означает «не менять».

**Скорость.** Бот проверяет таблицу каждые 5 секунд (`SHEETS_POLL_SECONDS`) одним лёгким запросом и
синхронизируется, когда правки перестали меняться — примерно через 5–10 секунд после того, как вы
закончили печатать. Раз в 30 минут выполняется полная синхронизация на всякий случай.

## Внешние интеграции

- **Telegram** — только push-уведомления (провал/прерывание задачи) через Bot API (httpx).
- **Google Sheets** — синхронизация через service-account; каждая строка валидируется отдельно, невалидные строки пропускаются и не перезаписываются экспортом.
- **Gmail** — read-only импорт писем от whitelist-отправителей (`support@liteserver.nl`, `admin@ztv.su`), точное сравнение адреса.
- **DeepSeek** — семантическая классификация входящих сообщений.

## База данных

SQLite через SQLAlchemy (async) и aiosqlite. Схема управляется Alembic:

```bash
alembic upgrade head     # применить миграции
alembic check            # проверить расхождение моделей и миграций
alembic downgrade base   # откатить все миграции
```

## Запуск

```bash
python -m app
```

Один долгоживущий процесс (для systemd): восстановление «зависших» задач, запуск
планировщика (health check, ежедневные напоминания и — если настроены — синхронизация
Google Sheets, импорт Gmail, классификация входящих) и Telegram long polling.
Работает до SIGTERM/SIGINT, затем корректно останавливается. Код выхода 1 — не
удалось запуститься (например, не применены миграции), 2 — неверная конфигурация.

Разовая авторизация Gmail (открывает браузер для OAuth-согласия):

```bash
python -m app.gmail
```

## Безопасность

Секреты хранятся только в `.env` и внешних credential-файлах и не должны попадать
в Git. `.gitignore` исключает `.env`, credential-`*.json` и `*.sqlite3`. Токены,
ключи и тела писем не логируются.

## Структура проекта

```text
app/
    config.py               # настройки (pydantic-settings)
    db.py                   # async-движок, сессия, declarative base

    reminders.py            # логика напоминаний
    expenses.py             # логика расходов

    notifications.py        # Telegram-уведомления
    inbox.py                # сервис входящих сообщений

    telegram/               # клиент Telegram Bot API

    deepseek/               # клиент DeepSeek и схемы классификации
alembic/                    # миграции
tests/                      # тесты
```
